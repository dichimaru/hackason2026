# Teams 連携

### 4.4 Teams 連携方式(Workflows の Webhook)
Webhook は「受付用 URL に POST すると Teams に投稿される」仕組みで、**投稿専用**(返信や押下はアプリに戻らない)。
アプリは2種類の Webhook URL を使う。

| 用途 | Webhook | 宛先 | 使う通知 |
|------|---------|------|----------|
| DM | Workflows「Webhook 要求を受信したとき」→「チャットまたはチャネルにカードを投稿」(**Flow bot として、受信した宛先のチャットに投稿**) | リクエストの `recipient`(社員の UPN) | invite / remind |
| チャネル | 同上で、投稿先を固定のチャネルにしたもの | 固定のチャネル | result(当選結果画面 W10 の URL) |

DM 用の Webhook に送る JSON(案):
```json
{ "recipient": "yamada@contoso.onmicrosoft.com",
  "title": "12/04(金) 東京 掃除当番の出欠をお願いします",
  "body": "掃除日 12/04(金) 16:00 / 締切 12/04(金) 13:00",
  "buttons": [
    { "label": "出席する", "url": "https://<app>/a/<token>?r=attend" },
    { "label": "欠席する", "url": "https://<app>/a/<token>?r=absent" } ] }
```
**回答リンク(クリックで回答が記録される)**
| リンク | 動作 |
|---|---|
| `GET /a/{token}?r=attend` / `?r=absent` | 出席/欠席を記録し、W2 回答完了ページを返す。締切までは何度でも上書き可。締切後は記録しない |
- **冪等**にする(同じリンクを何度開いても結果は同じ)。Teams やセキュリティ製品がリンクを自動で先読みしても、締切まで反対のリンクで上書きできるので実害は小さい。
- `token` は (回, 社員) ごとに一意で推測不能(128bit)。
- 通知は `Notifier` インターフェースで抽象化し、Webhook 実装で開始、後から Bot に差し替え可能にする。
- 開発中は Webhook 未設定でもログ出力のモック実装で動かせる。

**宛先の ID は UPN(ユーザープリンシパル名)を採用**: Microsoft 365 管理センター →「アクティブなユーザー」→ エクスポートの CSV に全員分が入っており、取得しやすい(Teams のプロフィールでも確認できる)。アプリへは W7 で1人ずつ登録する(取り込み機能は持たない)。AAD Object ID は GUID で扱いにくい。社内メールとは別なので `employees.teams_upn` に保存する。

**管理者への依頼内容**
1. 全社員の UPN の CSV(氏名・UPN)を共有してもらう
2. 通知用のチャネルを決め、DM 用 / チャネル用の Workflows(Webhook)を作成してもらい、URL を共有してもらう
- **要確認(Teams 側の設定作業)**: DM 用 Workflows で「宛先をリクエストから受け取って、その人への Flow bot チャットに投稿」を組めること。組織のポリシーで外部からの DM 用フローが禁止されていないか。


### Teams 通知(参考)
```
① 出欠のお願い (DM / 個人別リンク):
           🧹 12/04(金) 東京 掃除当番の出欠をお願いします
           掃除日 12/04(金) 16:00 / 締切 12/04(金) 13:00
           [ 出席する ]  [ 欠席する ]   ← クリックで回答が記録される

② リマインド (DM / 未回答者のみ・11:00):
           ⏰ 出欠のご回答がまだです。締切(13:00)まであと2時間です
           [ 出席する ]  [ 欠席する ]

③ 結果 (チャネル投稿・13:05。回ごとに投稿。当選結果画面 W10 への URL だけ):
           🎉 12/04(金) 東京の掃除当番が決まりました
           https://<app>/results/<回の public_token>

```
