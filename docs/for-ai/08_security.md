# 8. セキュリティ

守るもの: **社員情報**(氏名・部署・所属エリア・Teams UPN)と、管理操作(回の作成・中止、社員・道具の変更)。
アプリが持つ個人情報は上の4項目だけにする(メールアドレスなどは持たない)。

## 8.1 管理者の認証 (ID/パスワード)
- 管理者は社員の一部。ログイン情報は `employees` ではなく別テーブル `admin_accounts` に持つ。
  - 一般の社員の行にパスワード関連の列を持たない。
  - 社員一覧などの読み出しでハッシュが混ざらない。
- パスワードは **Argon2id(または bcrypt)でハッシュ化**して保存する。平文・可逆な暗号化では保存しない。
- パスワードの条件: 12文字以上。ID と同じ文字列は不可。
- 初期パスワード: 管理者が別の管理者を作るときに一時パスワードを設定し、**初回ログイン時に変更を必須**にする(`must_change_password`)。
- 総当たり対策: **5回連続で失敗したら15分ロック**(`failed_login_count`, `locked_until`)。失敗時のメッセージは「ID またはパスワードが違います」に統一し、ID が存在するかを教えない。
- 最初の管理者: 初期データ投入時に1人だけ作る(一時パスワード + 初回変更必須)。固定の既定パスワードは持たない。
- 最後の1人の管理者は外せない(管理画面に誰も入れなくなるため)。

## 8.2 セッション
- ログイン成功時にランダムなセッション ID(256bit)を発行し、Cookie に入れる。DB(`admin_sessions`)には**ハッシュだけ**を保存する。
- Cookie は `HttpOnly` / `Secure` / `SameSite=Lax`。
- 有効期限: 最後の操作から30分で切れる。ログインから最長8時間。
- 次のときは、その管理者のセッションをすべて消す: ログアウト、パスワード変更、管理者から外したとき、社員を休止にしたとき。
- 管理画面の更新操作(POST/PUT/DELETE)は **CSRF トークン**を必須にする。

## 8.3 ログイン不要のページ
| ページ | 出す情報 | 対策 |
|---|---|---|
| W2 回答完了 (`/a/{token}`) | 本人の氏名、回の日付・エリア、本人の回答 | token は (回, 社員) ごとの128bit 乱数。他人の情報は出さない |
| W10 当選結果 (`/results/{public_token}`) | その回の当番の氏名、道具・在庫・ポイント | URL は回ごとの128bit 乱数 (`cleaning_events.public_token`)。連番の id では開けない(他の回の結果を順に抜かれないように)。部署・UPN は出さない |

- 両ページとも検索エンジンに載せない(`noindex`)。
- token・public_token・UPN はアプリのログに出さない。

## 8.4 管理画面
- 管理画面と管理 API は、ログインした管理者だけが使える(未ログインはログイン画面へ)。
- 社員の UPN を出すのは管理画面(W7)だけ。
- 管理操作は **操作ログ**(`audit_logs`)に残す: 誰が・いつ・何をしたか(ログイン、回の作成・中止、社員・道具・管理者の変更)。ログに個人情報の中身(UPN など)は入れず、対象の id だけを書く。

## 8.5 通信・秘密情報
- すべて HTTPS。HTTP は HTTPS へ転送する。
- Webhook URL(DM 用・チャネル用)は秘密情報として環境変数に置く。リポジトリ・画面・ログに出さない。
- DB への問い合わせは、すべてプレースホルダ(パラメータ化)で組み立てる。
