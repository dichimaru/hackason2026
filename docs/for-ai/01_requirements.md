# 1〜2. 要件整理・全体フロー

## 1. 要件整理

| # | 要件 |
|---|------|
| R1 | Teams に「出欠回答リンク」を投稿する |
| R2 | 締切前に、未回答者へリマインドする |
| R3 | 抽選対象は **「出席」と回答した人のみ** |
| R4 | **前回当選した人は除外**して抽選する(連続で当番にならない) |

### 用語
- **回(イベント)**: 1回の掃除機会。掃除日・締切・抽選日時を持つ。
- **当選 = 当番になること**。
- **回**: エリアごと(大阪の回・東京の回)。
- **前回**: 同じエリアで直前に抽選済みの回(`drawn`。中止した回は含まない)。

### 設計判断: 「前回当選者は除外」の扱い(最重要)
サイクル(全員一巡するまで除外)方式は採らない。周の切り替わりで**連続当選**が起こりうるため。

- 除外対象 = **直前の回の当選者**(これだけ)。2回前以前の当選者は、また当たりうる
- **当番が決まった後の辞退はない**(抽選結果は変更しない)
- 抽選対象が枠数に満たない場合(出席者が少ない回)は、**前回当選者の中から不足分だけ補充**する。
  この場合は管理者に警告を出し、結果に「連続当番あり」と記録する(例外運用)
- 履歴テーブルを引くだけなので、状態(周の進捗など)を別に持たない

## 2. 全体フロー

```
[自動]    毎週金曜の朝(例: 09:00)に、その日の回をエリアごとに自動作成し、出欠 DM を送る (設定は W9)
          ※出欠・リマインド・締切・抽選・結果発表はすべて掃除当日(金曜)の掃除開始前に行う
[管理者]  (臨時の回は手動で作成 W3)
    │
    ▼
[Teams]   ①全員の DM に「個人別の出欠リンク」を送信 (Adaptive Card)  ──▶ 社員が出席/欠席を回答
    │
    │  リマインド (掃除当日。例: 11:00)
    ▼
[Teams]   ②未回答者の DM に、個人別リンクでリマインド
    │
    │  締切 (掃除当日。例: 13:00) → 回答クローズ
    ▼
[抽選]    出席者 − 前回の当選者 → 抽選 (不足時は前回当選者から補充+警告)
    ▼
[Teams]   ③結果発表: 当選結果画面 (W10・誰でも見られる) の URL を、回ごとにチャネルに投稿
```

### 回のステータス遷移
```
open (作成と同時に出欠受付。締切は時刻で判定) ─抽選→ drawn
  │
  └─ 中止 → cancelled
```
