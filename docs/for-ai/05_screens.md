# 5. 画面ワイヤーフレーム

見た目は [../wireframes/index.html](../wireframes/index.html)。Figma は古い版なので参照しない。
各画面に「項目 → テーブル.列」を付ける。**画面の項目はすべて、列か列からの計算で出せること**(テーブル定義と対)。

### W0. 画面一覧・遷移
```
【社員】  DM の「出席する/欠席する」リンクをクリック ─▶ その場で記録 ─▶ [W2 回答完了ページ]
【誰でも】Teams のチャネルの URL ─▶ [W10 当選結果画面]
【管理者】[W1 回一覧] ─▶ [W4 回の詳細]   [W3 臨時の回の作成]
          ヘッダーのナビ: [回一覧] [当番履歴 W6] [社員 W7] [掃除道具 W8] [自動作成の設定 W9]
```
管理者画面は、管理者ごとの ID/パスワードでログインして入る(W0-1。08_security.md)。W5(管理者用の抽選結果)は W10 と内容が重なるため廃止。

### 管理画面の CRUD 一覧
行を消すと出欠・当番の参照が壊れるため、削除は下の扱いで代える。

| 対象 (テーブル) | 一覧・参照 | 作成 | 更新 | 削除 |
|---|---|---|---|---|
| 回 (cleaning_events) | W1 / W4 | 自動作成 / W3 | なし | W4-2 中止 (status=cancelled) |
| 社員 (employees) | W7 | W7-1 | W7-2 | W7-2 で休止 (active=0)。行は消さない |
| 管理者 (admin_accounts) | W7 のバッジ | W7-2 で管理者にする | W0-2 パスワード変更 | W7-2 で管理者から外す (最後の1人は不可) |
| 掃除道具 (tools) | W8 | W8-1 | W8-2 (在庫数の更新を含む) | 在庫 0 にする (当番を割り当てない)。行は消さない |
| 自動作成の設定 (schedule_settings) | W9 | 初期データ | W9 | なし |
| 当番 (duties) | W4 / W6 / W10 | 抽選 | なし | なし |
| 出欠 (attendances) | W4 | 回の作成時 | 社員が DM のリンクで回答 (W2) | なし |
| エリア (areas) | 固定。画面なし | | | |

### W0-1. 管理者ログイン
```
┌──────────────────────────────┐
│ 管理者ログイン                  │
│ ログイン ID  [            ]    │
│ パスワード   [            ]    │
│              [ ログイン ]       │
│ (失敗) ID またはパスワードが違います │
│ (ロック中) しばらくしてからお試しください │
└──────────────────────────────┘
```
| 項目 | 出どころ |
|---|---|
| ログイン ID・パスワード | `admin_accounts.login_id / password_hash`(ハッシュと照合) |
| 失敗回数・ロック | `admin_accounts.failed_login_count / locked_until` |
| ログイン後 | `admin_sessions` に行を作り、Cookie を発行。`must_change_password=1` なら W0-2 へ |

```
│ 新しいパスワード   [          ] │
│ 新しいパスワード(確認)[        ] │
│ ※12文字以上。ID と同じものは不可  │
```

### W2. 回答完了ページ (社員 / スマホ)
回答用の画面は無い。DM のリンクをクリックした時点で記録され、このページが開く。
```
┌──────────────────────────────┐
│ 12/04(金) 東京 掃除当番          │
│ [出席で回答しました ✔]          │
│ 山田 太郎 さん                  │
│ 回答日時 12/04(金) 10:21        │
│ 締切(13:00)までは、DM のもう一方 │
│ のリンクで変更できます。          │
└──────────────────────────────┘
 欠席: 「欠席で回答しました」 / 締切後: 「回答は締め切られました」(記録しない)
 前回の当選者: 「前回の当番のため、今回は抽選対象外です」
```
| 項目 | 出どころ |
|---|---|
| 日付・エリア・締切 | token → `attendances.event_id` → `cleaning_events` |
| 名前 | `attendances.employee_id` → `employees.name` |
| 回答・回答日時 | `attendances.response / responded_at` |
| 前回の当選者か | 同じエリアの前回の `duties` にこの社員がいるか(計算) |

### W3. 臨時の回の作成 (管理者)
通常の回は毎週自動で作成される。この画面は臨時の回を足すためのもの。作成と同時に出欠 DM を送る。
```
┌──────────────────────────────────────────────────────────────┐
│ ← 回一覧   臨時の回を作成                                       │
│ エリア     ( ◉ 東京  ○ 大阪 )   当番 6名 (道具の必要人数の合計)  │
│ 掃除日     [ 2026-12-13 ]   開始時刻 [ 16:00 ]                  │
│ リマインド [ 12/13 11:00 ]  出欠締切 [ 12/13 13:00 ]  抽選 [ 12/13 13:05 ] │
│                                   [ 作成して出欠 DM を送る ]     │
└──────────────────────────────────────────────────────────────┘
```
| 項目 | 出どころ |
|---|---|
| エリア・掃除日・開始時刻・リマインド・出欠締切・抽選 | `cleaning_events.area_id / event_date / start_time / remind_at / attendance_deadline / draw_at`(source='manual') |
| 当番人数(表示のみ) | そのエリアの `tools`(stock>0)の `required_people` の合計 |

### W4. 回の詳細 (管理者)
```
┌──────────────────────────────────────────────────────────────┐
│ ← 回一覧   12/04(金) 東京   回答受付   締切まで あと 2時間        │
│ 出席 15 / 欠席 2 / 未回答 3      当番 6名                       │
│ 抽選の対象: 出席 15 − 前回当選 6 = 9 / 当番 6名   (13:05 に自動抽選)│
│  ⚠ 対象が当番人数より少ない場合は、前回当選者から補充(連続当番)    │
│ [すべて][出席][欠席][未回答]                                     │
│ 氏名        回答     抽選                                       │
│ 山田 太郎   出席     対象                                       │
│ 佐藤 花子   出席     除外 (前回 11/27 に当選)                     │
│ 小林 誠     未回答   -                                          │
│                                          [ この回を中止する ]   │
│ (抽選後) 当番: 掃除機 山田 太郎 / 鈴木 一郎  アルコールスプレー 渡辺 桜 … (連続当番には ⚠) │
└──────────────────────────────────────────────────────────────┘
```
| 項目 | 出どころ |
|---|---|
| 日付・エリア・状態・締切まで | `cleaning_events`(残り時間は計算) |
| 出席/欠席/未回答・一覧 | `attendances` + `employees.name` |
| 当番人数 | `tools`(stock>0)の `required_people` の合計 |
| 前回当選・除外 | 同じエリアの前回の `duties`(計算) |
| 抽選後の当番・連続 | `duties` + `tools.name` + `employees.name`。連続は前回の `duties` との比較(計算) |
| 中止 | `cleaning_events.status='cancelled'` |

### W7-1. 社員の追加 / W7-2. 社員の編集 (管理者)
```
│ 氏名 [        ]  部署 [      ]  エリア (○東京 ○大阪)                 │
│ Teams UPN [                         ] (空欄可。空欄の社員には DM を送れない) │
│ (編集のみ) 状態 (◉有効 ○休止)                                        │
│ (編集のみ) 管理者  [ ] 管理者にする → ログイン ID [      ] 一時パスワード [      ] │
│            (管理者の社員) [管理者から外す]  ※最後の1人は外せない            │
│                                               [キャンセル][保存]      │
```
| 項目 | 出どころ |
|---|---|
| 氏名・部署・エリア・UPN・状態 | `employees` の各列。UPN は重複不可 |
| 管理者にする / 外す | `admin_accounts` の行の作成 / 削除(外すと、その人のセッションも消える)。一時パスワードは `must_change_password=1` |

エリア・状態・管理者の変更は、次に作られる回から反映する。休止にすると、管理者のセッションも消す。

```
│  掃除機             人数 2  在庫 2台  床全体に掃除機をかける      編集 │
│  アルコールスプレー  人数 1  在庫 3本  テーブルを拭く / ホワイトボード 編集 │
│  スポンジ           人数 2  在庫 4個  シンクを磨く / 電子レンジ    編集 │
│  トイレブラシ        人数 1  在庫 1本  便器を磨く / 手洗い場       編集 │
│  ほうき  人数 1  在庫 0 ⚠ 当番を割り当てない(合計に入らない)  編集 │
```

```
│ エリア (○東京 ○大阪)  ※編集では変更不可                               │
```

### W10. 当選結果画面 (誰でも / ログイン不要・スマホ)
Teams のチャネルに回ごとに投稿する URL(`/results/{public_token}`。連番の id は使わない)の先。**その回(東京の回 / 大阪の回)の当番**を表示する。
```
┌──────────────────────────────┐
│     今週の掃除当番はこちら!      │
│     12/04(金) 東京 16:00〜      │
│ ┌──────────────────────────┐ │
│ │ A 掃除機 担当               │ │
│ │ 山田 太郎 さん  鈴木 一郎 さん │ │
│ │ 掃除のポイント  使う道具       │ │
│ │ 床全体に掃除機   掃除機 2台    │ │
│ │ をかける                     │ │
│ └──────────────────────────┘ │
│ ┌ B アルコールスプレー 担当 ──┐ │
│ │ 渡辺 桜 さん                 │ │
│ │ テーブルをアルコールで拭く     │ │
│ │ ホワイトボードをきれいにする    │ │
│ │ 使う道具: アルコールスプレー 3本│ │
│ └──────────────────────────┘ │
│  C スポンジ 担当 / D トイレブラシ 担当 … │
│ 当番のみなさん、よろしくお願いします! │
│        [ 結果を共有 ]            │
└──────────────────────────────┘
 抽選前の回: 「13:05 に抽選します」 / 中止の回: 「中止」 / 出席者なし: 「出席者がいません」
```
- 元の Figma の結果画面の構成(見出し・担当ごとのカード A〜D・当番・掃除のポイント・使う道具と在庫・締めの一言・結果を共有)に合わせる。
- 「結果を共有」は、この画面の URL をコピーするだけ(データは使わない)。
- 元の Figma にあった次の2つは載せない。
  - 落選者向けの「今週は回避」: この画面はログイン不要で、見ている人が誰か分からない。
  - 在庫 0 の道具の「更新」ボタン: 在庫 0 の道具には当番を割り当てないので、結果に出てこない。在庫の更新は W8 で行う。
| 項目 | 出どころ |
|---|---|
| 掃除日・開始時刻・エリア・状態 | `cleaning_events.event_date / start_time / area_id→areas.name / status` |
| カード(A〜D の順)・道具・在庫・ポイント | `duties.tool_id → tools.name / stock / description`(A〜D は表示順の番号で、列は持たない) |
| 当番 | `duties.employee_id → employees.name` |
